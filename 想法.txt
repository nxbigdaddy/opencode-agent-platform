5.4 标准化策略
在全局配置中创建标准化命令（如 ERP 单据生成），固定提示词模板和工具调用流程
所有租户继承该全局命令，禁止修改核心配置
确保同一任务在所有租户环境下执行路径完全一致
六、数据库隔离方案（SQL Server 不改原库）
适用场景：已有 SQL Server ERP 数据库，不改变原表结构
方案：行级安全策略（Row-Level Security, RLS）
表格
步骤	操作
Step 1	给所有租户相关表添加 TenantId 列
Step 2	创建内联表值函数，通过 SESSION_CONTEXT 获取当前租户 ID 进行数据过滤
Step 3	创建安全策略，绑定函数和表
Step 4	应用层在数据库连接时设置会话上下文的 TenantId
效果：在数据库层强制隔离，无需修改原表结构和业务代码。


关键设计原则总结
标准化优先：企业环境中，访问 ERP、生成单据等任务正确路径只有一条，必须全局标准化
可控优于自主：对话式控制比完全自主更适合生产环境，避免多路径执行带来的不确定性
租户隔离：通过 session_id + 独立 Schema/RLS 实现数据与代码空间隔离
零侵入集成：对现有 SQL Server ERP 数据库采用行级安全策略，不改原库结构
