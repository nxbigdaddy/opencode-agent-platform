## 1. 项目概述

### 1.1 项目背景

本项目旨在将 OpenCode CLI（开源 AI 编程助手）转化为生产级远程 Agent 引擎，构建一个支撑多用户、多会话、多工具的 AI 对话服务平台。通过 Web 界面和 API 接口，让非技术用户也能利用 AI Agent 的强大能力完成编程、数据分析、文档编写等任务。

### 1.2 项目范围

**包含**：
- Web 对话界面（实时聊天、文件上传、代码展示）
- 管理后台（用户管理、用量统计、系统配置）
- 多租户会话管理系统
- Agent 配置与路由系统
- MCP 工具生态集成
- 企业微信/钉钉机器人接入
- 审计与计费系统

**不包含**：
- LLM 模型训练与微调
- 自研代码编辑器
- 移动端原生 App（使用 PWA 替代）

### 1.3 术语定义

| 术语 | 定义 |
|------|------|
| **Agent** | AI 智能体，具备特定角色和工具权限的 AI 助手 |
| **MCP** | Model Context Protocol，模型上下文协议，用于扩展 AI 工具能力 |
| **SSE** | Server-Sent Events，服务器推送事件，实现流式响应 |
| **Session** | 用户与 AI 的一次完整对话上下文 |
| **Workspace** | 用户会话的独立工作目录，实现数据隔离 |
| **Gateway** | API 网关，负责请求路由、认证、限流等 |
| **OpenCode** | 开源 AI 编程助手 CLI 工具 |

## 2. 业务目标

### 2.1 功能性目标

1. **多用户支持**：支持企业内数百名用户同时使用
2. **多会话管理**：每个用户可创建多个独立会话
3. **多 Agent 切换**：支持 Build、Plan、Review 等不同角色的 Agent
4. **工具扩展**：通过 MCP 协议集成外部工具（数据库查询、API 调用等）
5. **实时对话**：SSE 流式传输，支持代码高亮和文件展示
6. **权限控制**：基于角色的访问控制（RBAC）

### 2.2 非功能性目标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| **并发用户数** | 500+ | 单实例支持 |
| **响应延迟** | P99 < 30s | 首字返回时间 < 3s |
| **可用性** | 99.9% | 年停机时间 < 8.76 小时 |
| **数据持久化** | 7年 | 审计日志保留 |
| **扩展性** | 水平扩展 | 支持多实例部署 |

## 4. 架构设计原则

### 4.1 设计原则

1. **分层解耦**：表现层、网关层、引擎层独立部署、独立扩展
2. **接口契约**：所有层间通信通过定义良好的 API 接口
3. **状态外置**：会话状态存储在 Redis，不依赖进程内存
4. **工具隔离**：每个 MCP 工具独立进程，故障不相互影响
5. **安全默认**：所有接口默认需要认证，工具默认禁用

### 4.2 技术约束

- **不使用 Java**：全栈使用 Python + JavaScript/TypeScript
- **不使用 Vue**：前端使用 React
- **Linux 优先**：生产环境使用 Ubuntu 22.04/24.04
- **开源优先**：核心组件优先选择开源方案

### 5.2 架构分层说明

#### 5.2.1 表现层 (Presentation Layer)

**职责**：
- 提供用户交互界面
- 管理客户端状态（草稿、主题、设置）
- 实现 SSE 连接和消息渲染
- 处理文件上传和下载

**组件**：
- Web 对话端（React SPA）
- 管理后台（React SPA）
- 企微/钉钉 Webhook 适配器
- 第三方系统回调处理器

#### 5.2.2 网关层 (Gateway Layer)

**职责**：
- 统一入口，路由所有请求
- JWT 认证与授权
- 速率限制与流量控制
- 会话状态管理
- Agent 路由决策
- MCP 服务注册与发现
- 审计日志记录
- OpenCode Server 代理

**组件**：
- FastAPI ASGI 应用
- Redis 缓存与消息队列
- PostgreSQL 持久化存储
- 认证中间件
- SSE 代理服务

#### 5.2.3 引擎层 (Engine Layer)

**职责**：
- 执行 AI 推理
- 管理工具调用
- 维护工作区隔离
- 处理文件系统操作

**组件**：
- OpenCode Server（主进程）
- MCP Server 集群（独立进程）
- 工作区文件系统
- systemd 进程守护

### 6.2 技术选型详细说明

#### 6.2.1 为什么选 FastAPI 而不是 Flask/Django？

1. **原生异步**：基于 Starlette + Pydantic，原生支持 async/await
2. **SSE 支持**：内置 StreamingResponse，轻松实现 SSE 流式传输
3. **自动文档**：基于 OpenAPI 自动生成 Swagger/ReDoc 文档
4. **类型安全**：Pydantic 模型提供请求/响应验证和序列化
5. **性能**：在独立基准测试中，FastAPI 性能接近 Node.js 和 Go

#### 6.2.2 为什么选 React 而不是 Vue？

1. **生态成熟度**：React 生态更丰富，尤其是企业级组件库
2. **TypeScript 支持**：React 对 TS 的支持更成熟
3. **团队技能**：假设团队已有 React 经验
4. **SSR 生态**：Next.js 生态更成熟（未来扩展）

#### 6.2.3 为什么选 PostgreSQL 而不是 MySQL？

1. **JSONB 支持**：原生 JSONB 字段，适合存储动态工具配置
2. **全文检索**：内置全文检索能力
3. **ACID**：更严格的 ACID 保证
4. **扩展性**：支持 PostGIS、TimescaleDB 等扩展

### 7.2 关键组件详细设计

#### 7.2.1 SSE Proxy Service

**职责**：
- 接收前端 SSE 连接请求
- 建立与 OpenCode Server 的 SSE 连接
- 双向转发事件流
- 连接断开时自动重连
- 心跳保活

**实现要点**：
- 使用 FastAPI `StreamingResponse`
- 维护连接池（前端 <-> OpenCode）
- 支持连接级别取消（Cancel Token）
- 超时控制（默认 60s）

#### 7.2.2 Session Manager

**职责**：
- 创建/销毁用户会话
- 维护用户会话与 OpenCode 会话的映射关系
- 会话状态机管理（active/archived/deleted）
- 会话元数据管理（标题、工作区、Agent）

**状态机**：

#### 7.2.3 Agent Router

**职责**：
- 根据用户请求选择合适的 Agent
- 管理 Agent 配置（系统提示词、工具白名单、模型参数）
- 动态加载/卸载 Agent
- Agent 权限检查

**路由策略**：

| 策略 | 说明 | 示例 |
|------|------|------|
| **用户指定** | 用户通过 UI 选择 Agent | `@general` |
| **内容匹配** | 根据消息内容自动选择 | 代码相关 → Build Agent |
| **历史继承** | 新消息继承会话当前 Agent | 会话保持 |
| **默认回退** | 无匹配时使用默认 Agent | Build Agent |

#### 7.2.4 MCP Registry

**职责**：
- MCP 服务注册与发现
- 健康检查与心跳监控
- 负载均衡（多实例 MCP）

## 9. 扩展性设计

### 9.1 水平扩展策略

#### 9.1.1 网关层扩展

- **无状态设计**：所有会话状态存储在 Redis
- **负载均衡**：Nginx 反向代理到多个 Gateway 实例
- **Sticky Session**：可选 SSE 连接粘性会话

#### 9.1.2 OpenCode Server 扩展

- **多实例部署**：每个实例独立服务部分会话
- **会话亲和性**：通过 Session ID 哈希路由到特定实例
- **共享存储**：工作区使用共享文件系统（NFS/S3）

#### 9.1.3 MCP 服务扩展

- **多实例注册**：相同 MCP 服务注册多个实例
- **负载均衡**：网关层轮询或随机选择实例
- **健康检查**：自动剔除不健康实例

### 9.2 未来演进路线

| 阶段 | 扩展能力 | 技术方案 |
|------|---------|---------|
| **Phase 1** | 单实例 | Docker Compose |
| **Phase 2** | 多实例 | Kubernetes + Helm |
| **Phase 3** | 多区域 | 多 K8s 集群 + 全局负载均衡 |
| **Phase 4** | 多云 | 混合云部署 + 服务网格 |
